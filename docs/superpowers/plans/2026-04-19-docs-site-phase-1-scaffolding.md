# ServiceConnect Docs Site — Phase 1: Scaffolding

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a complete static-site build pipeline (Astro + Starlight + DocFX) that publishes an empty ServiceConnect docs site to GitHub Pages at `https://r-suite.github.io/ServiceConnect-CSharp/` via a GitHub Actions workflow on push to `main`.

**Architecture:** Astro/Starlight produces the chrome and Markdown-driven content; DocFX generates static HTML for the API reference into `website/public/api/` so Astro mounts it as static assets at `/api/`. A single GitHub Actions workflow builds .NET → DocFX → Astro and deploys via `actions/deploy-pages`. No content writing happens in this phase — the deliverable is "empty site building and deploying end-to-end."

**Tech Stack:** Astro + Starlight (Node 20), DocFX (.NET tool, pinned via tool manifest), Pagefind (ships with Starlight), GitHub Actions, GitHub Pages.

**Out of scope for Phase 1:** logo/branding, homepage design, Learn/Samples/Releases content, cross-track search indexing of `/api/` pages, theming DocFX to match Starlight. All of those are Phases 2–4.

**Reference:** `docs/superpowers/specs/2026-04-19-serviceconnect-docs-site-design.md`

## Task 2: Enable XML doc generation for `src/` projects

**Files:**
- Create: `src/Directory.Build.props`

**Context:** `<GenerateDocumentationFile>` is not currently set on any csproj in `src/`. Without it, the .NET build does not emit the `.xml` files DocFX reads to produce the API reference. A `Directory.Build.props` at `src/` applies to every project beneath it without per-project edits, and crucially does not affect the test projects in other directories.

CS1591 ("missing XML comment for publicly visible type") would be very noisy on a partially documented codebase, so we suppress it.

- [ ] **Step 1: Verify no `Directory.Build.props` already exists at `src/` or repo root**

Run: `ls src/Directory.Build.props 2>/dev/null; ls Directory.Build.props 2>/dev/null`
Expected: both return no output (file does not exist).

- [ ] **Step 2: Try a build first to confirm the absence of XML files (failing test)**

```bash
dotnet build src/ServiceConnect/ServiceConnect.csproj -c Release --nologo -v quiet
ls src/ServiceConnect/bin/Release/net10.0/ServiceConnect.xml 2>&1
```

Expected: build succeeds, but `ls` reports "No such file or directory" — the XML file is not produced.

- [ ] **Step 3: Create the props file**

Create `src/Directory.Build.props`:

```xml
<Project>
  <PropertyGroup>
    <!-- Emit XML documentation files so DocFX can build the API reference. -->
    <GenerateDocumentationFile>true</GenerateDocumentationFile>
    <!-- Suppress CS1591 (missing XML comment for publicly visible type or member). -->
    <NoWarn>$(NoWarn);CS1591</NoWarn>
  </PropertyGroup>
</Project>
```

- [ ] **Step 4: Rebuild and confirm the XML file is now produced (passing test)**

```bash
dotnet build src/ServiceConnect/ServiceConnect.csproj -c Release --nologo -v quiet
ls src/ServiceConnect/bin/Release/net10.0/ServiceConnect.xml
```

Expected: file is listed (no error).

- [ ] **Step 5: Build the full solution to verify no regressions across other projects**

```bash
dotnet build src/ServiceConnect.sln -c Release --nologo -v minimal
```

Expected: build succeeds with no errors. Warnings unrelated to CS1591 are acceptable.

- [ ] **Step 6: Commit**

```bash
git add src/Directory.Build.props
git commit -m "build: emit XML doc files for src projects (DocFX prerequisite)"
```

## Task 6: Write the DocFX configuration

**Files:**
- Create: `website/docfx/docfx.json`
- Create: `website/docfx/filterConfig.yml`

**Context:** DocFX has two stages combined into one `dotnet docfx` invocation: `metadata` (extract API metadata from the compiled assemblies + XML doc files into YAML) and `build` (render YAML into HTML). We point `metadata` at the solution and `build` to output HTML into `website/public/api/` so Astro mounts it as static content. The filter file excludes internal types and the test project.

- [ ] **Step 1: Verify the DocFX config dir does not exist (failing test)**

```bash
ls website/docfx 2>&1
```

Expected: `ls: cannot access 'website/docfx': No such file or directory`.

- [ ] **Step 2: Create the DocFX directory and the filter config**

```bash
mkdir -p website/docfx
```

Create `website/docfx/filterConfig.yml`:

```yaml
apiRules:
  # Exclude all test projects.
  - exclude:
      uidRegex: ^ServiceConnect\.UnitTests
      type: Namespace
  - exclude:
      uidRegex: ^ServiceConnect\.EndToEndTests
      type: Namespace
  # Exclude any type whose visibility is internal/private.
  - exclude:
      hasAttribute:
        uid: System.Runtime.CompilerServices.CompilerGeneratedAttribute
```

- [ ] **Step 3: Create the DocFX project config**

Create `website/docfx/docfx.json`:

```json
{
  "metadata": [
    {
      "src": [
        {
          "files": ["src/ServiceConnect.sln"],
          "src": "../.."
        }
      ],
      "dest": "../../website/_docfx_metadata",
      "filter": "filterConfig.yml",
      "disableGitFeatures": false,
      "outputFormat": "mref"
    }
  ],
  "build": {
    "content": [
      {
        "files": ["**/*.{md,yml}"],
        "src": "../_docfx_metadata"
      }
    ],
    "globalMetadata": {
      "_appTitle": "ServiceConnect API Reference",
      "_appName": "ServiceConnect",
      "_enableSearch": false,
      "_disableContribution": true,
      "_disableNewTab": false
    },
    "dest": "../public/api",
    "template": ["default", "modern"],
    "postProcessors": ["ExtractSearchIndex"]
  }
}
```

Note: `_enableSearch: false` because Pagefind indexes the combined site after the Astro build; DocFX's own search would conflict. Cross-track search is a Phase 4 deliverable.

## Task 8: Write the GitHub Actions workflow

**Files:**
- Create: `.github/workflows/docs.yml`

**Context:** The workflow has two triggers: `push` to `main` (for actual deploys) and `workflow_dispatch` (so you can run it manually on any branch to verify it works without deploying). The deploy step is conditional on the run being from `main`. This avoids accidentally deploying half-finished feature work.

- [ ] **Step 1: Verify the workflow does not exist (failing test)**

```bash
ls .github/workflows/docs.yml 2>&1
```

Expected: `ls: cannot access '.github/workflows/docs.yml': No such file or directory`.

- [ ] **Step 2: Create the workflow file**

Create `.github/workflows/docs.yml`:

```yaml
name: Build and deploy docs site

on:
  push:
    branches: [main]
    paths:
      - 'website/**'
      - 'src/**'
      - 'filters/**'
      - '**/*.csproj'
      - '**/*.cs'
      - '.github/workflows/docs.yml'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: |
            8.0.x
            10.0.x

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: website/package-lock.json

      - name: Restore .NET tools (DocFX)
        run: dotnet tool restore

      - name: Build .NET solution (emits XML doc files)
        run: dotnet build src/ServiceConnect.sln --configuration Release --nologo

      - name: Build API reference (DocFX)
        run: dotnet docfx website/docfx/docfx.json

      - name: Install website dependencies
        working-directory: website
        run: npm ci

      - name: Build website (Astro + Starlight)
        working-directory: website
        run: npm run build

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: website/dist

  deploy:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```


Expected: `OK`.
