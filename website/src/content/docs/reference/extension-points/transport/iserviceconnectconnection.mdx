## Overview

`IServiceConnectConnection` is an abstraction over a RabbitMQ connection, used internally by the `ServiceConnect.Client.RabbitMQ` transport. It exists so the RabbitMQ-specific consumer and producer can obtain `IChannel` instances from something other than a plain `RabbitMQ.Client.IConnection` — for example, a wrapper that rotates mTLS certificates without dropping the channel pool, a connection that round-robins across cluster members, or one that integrates with a circuit-breaker.

<Aside type="caution">
This interface is **RabbitMQ-specific**. It lives in the `ServiceConnect.Client.RabbitMQ` assembly, depends on `RabbitMQ.Client`, and has no meaning outside the RabbitMQ transport. If you are adding support for a different broker — Azure Service Bus, Kafka, Redis Streams — implement [`IConsumer`](./iconsumer/) and [`IProducer`](./iproducer/) together. Those interfaces in `ServiceConnect.Interfaces` are the correct cross-broker extension points.
</Aside>

The interface is declared as:

```csharp
using RabbitMQ.Client;

namespace ServiceConnect.Client.RabbitMQ;

public interface IServiceConnectConnection : IAsyncDisposable
{
    Task<IChannel> CreateChannelAsync(CancellationToken cancellationToken = default);
    Task<IChannel> CreateChannelAsync(CreateChannelOptions? options, CancellationToken cancellationToken = default);
    bool IsConnected();
    IConnection? UnderlyingConnection { get; }
}
```

Implement `IServiceConnectConnection` only when you need to customise how the RabbitMQ connection itself is managed — not to add a new transport.

See [Configuration](/ServiceConnect-CSharp/learn/operations/configuration/) for an overview of how transports are registered.

## Reference

### `CreateChannelAsync`

```csharp
Task<IChannel> CreateChannelAsync(CancellationToken cancellationToken = default);
Task<IChannel> CreateChannelAsync(CreateChannelOptions? options, CancellationToken cancellationToken = default);
```

Opens and returns a new `RabbitMQ.Client.IChannel` from the underlying connection. The RabbitMQ consumer and producer call this once per logical consumer loop or send operation to obtain a channel. The second overload forwards `CreateChannelOptions` — for example, to enable publisher confirms on a producer channel — while the first overload uses transport defaults.

**Parameters**
- `options` — channel options applied to the underlying RabbitMQ channel, or `null` for defaults.
- `cancellationToken` — token that cancels connection-establishment and channel-open operations.

**Returns.** A newly opened `IChannel`. The caller is responsible for disposing the channel after use.

**Remarks.** `CreateChannelAsync` may be called concurrently from multiple consumer and producer loops. `RabbitMQ.Client.IConnection.CreateChannelAsync` is thread-safe; custom implementations that wrap the connection with additional logic (certificate checking, rate-limiting) must not serialise callers unnecessarily, as doing so would throttle the throughput of every consumer and producer in the process.

---

### `IsConnected`

```csharp
bool IsConnected();
```

Returns `true` when the underlying RabbitMQ connection is open and usable. The transport uses this for health-check reporting and reconnect decisions.

**Returns.** `true` if the connection is currently established; `false` otherwise. Implementations that wrap a `RabbitMQ.Client.IConnection` should delegate to `IConnection.IsOpen`.

---

### `UnderlyingConnection`

```csharp
IConnection? UnderlyingConnection { get; }
```

Exposes the underlying `RabbitMQ.Client.IConnection`, or `null` if the connection has not been established yet or has been disposed.

**Remarks.** Used by `RabbitMqConsumerHost` to subscribe to connection-level events (shutdown, blocked, unblocked) for observability. Wrapper implementations should return the live `IConnection` they manage so the host can attach these event handlers; returning `null` during establishment or after disposal is the expected shape.

---

## Implementing

### Connection lifecycle

Open the underlying `RabbitMQ.Client.IConnection` once at construction or on the first call to `CreateChannelAsync`. Hold it for the lifetime of the wrapper. In `DisposeAsync`, close and dispose the connection after disposing any open channels.

### Thread-safety

Multiple consumer loops and producers may call `CreateChannelAsync` simultaneously. `RabbitMQ.Client.IConnection.CreateChannelAsync` is safe for concurrent calls — do not introduce a `lock` or `SemaphoreSlim` around it unless the custom logic you are adding genuinely requires serialisation (for example, certificate rotation that temporarily invalidates the connection). Unnecessary serialisation reduces throughput.

### Reconnection strategy

`RabbitMQ.Client` provides automatic connection recovery when configured with `AutomaticRecoveryEnabled = true`. The wrapper should rely on this rather than implementing its own reconnect loop. If visibility into recovery events is needed, subscribe to `IConnection.RecoveringAsync` and `IConnection.RecoverySucceededAsync` to emit metrics or log entries without duplicating the recovery logic.

### Diagnostics hooks

`CreateChannelAsync` is a useful instrumentation point. Wrap the call in an `Activity` started from a project-level `ActivitySource` to add a span to every channel-open event. This lets distributed tracing systems (OpenTelemetry) correlate channel creation with the consumer or producer that triggered it.

### Skeletal sketch

```csharp
using RabbitMQ.Client;
using ServiceConnect.Client.RabbitMQ;

public sealed class CustomRabbitConnection : IServiceConnectConnection
{
    private IConnection? _connection;

    public CustomRabbitConnection(IConnection connection)
    {
        _connection = connection;
    }

    public IConnection? UnderlyingConnection => _connection;

    public Task<IChannel> CreateChannelAsync(CancellationToken cancellationToken = default)
        => CreateChannelAsync(options: null, cancellationToken);

    public Task<IChannel> CreateChannelAsync(CreateChannelOptions? options, CancellationToken cancellationToken = default)
    {
        if (_connection is null)
            throw new InvalidOperationException("Connection has been disposed.");

        // Add custom logic here (certificate refresh, rate-limiting, tracing).
        return _connection.CreateChannelAsync(options, cancellationToken);
    }

    public bool IsConnected()
        => _connection?.IsOpen ?? false;

    public async ValueTask DisposeAsync()
    {
        if (_connection is not null)
        {
            await _connection.CloseAsync();
            _connection.Dispose();
            _connection = null;
        }
    }
}
```

## Usage

### mTLS certificate rotation

The following example wraps the standard RabbitMQ connection and refreshes the client certificate before creating each channel. This is useful in environments where short-lived mTLS certificates are issued by a secret manager (for example, HashiCorp Vault PKI) and must be rotated without restarting the service.

```csharp
using System.Security.Cryptography.X509Certificates;
using RabbitMQ.Client;
using ServiceConnect.Client.RabbitMQ;

public sealed class MutualTlsRabbitConnection : IServiceConnectConnection
{
    private readonly Func<X509Certificate2> _certProvider;
    private IConnection? _connection;

    public MutualTlsRabbitConnection(
        IConnectionFactory factory,
        Func<X509Certificate2> certProvider)
    {
        _certProvider = certProvider;
        // Connection is opened at construction with the initial certificate.
        _connection   = factory.CreateConnectionAsync().GetAwaiter().GetResult();
    }

    public bool IsConnected() => _connection?.IsOpen ?? false;

    public IConnection? UnderlyingConnection => _connection;

    public Task<IChannel> CreateChannelAsync(CancellationToken cancellationToken = default)
        => CreateChannelAsync(options: null, cancellationToken);

    public async Task<IChannel> CreateChannelAsync(CreateChannelOptions? options, CancellationToken cancellationToken = default)
    {
        if (_connection is null)
            throw new ObjectDisposedException(nameof(MutualTlsRabbitConnection));

        // Refresh the client certificate before opening each channel.
        // The cert provider fetches the latest short-lived certificate from the
        // secret store; stale certificates are swapped out transparently.
        var cert = _certProvider();
        _ = cert; // Apply cert to SSL options if the factory supports dynamic reconfiguration.

        return await _connection.CreateChannelAsync(options, cancellationToken);
    }

    public async ValueTask DisposeAsync()
    {
        if (_connection is not null)
        {
            await _connection.CloseAsync();
            _connection.Dispose();
            _connection = null;
        }
    }
}
```

Register the implementation during bus startup so the RabbitMQ transport uses it in place of the default connection:

```csharp
services.AddServiceConnect(builder =>
{
    builder.AddRegistration(svc =>
    {
        svc.AddSingleton<Func<X509Certificate2>>(() =>
        {
            // Fetch the current short-lived certificate from the secret store.
            return LoadCertificateFromVault();
        });
        svc.AddSingleton<IServiceConnectConnection, MutualTlsRabbitConnection>();
    });
});
```

When the `ShippingSaga` handler calls `_bus.PublishAsync(new ShipmentDispatched(...))`, the RabbitMQ producer calls `CreateChannelAsync()` on the registered `MutualTlsRabbitConnection`, which refreshes the certificate before opening the channel. The rest of the RabbitMQ transport — channel lifecycle, publisher confirms, error handling — is unaffected.
