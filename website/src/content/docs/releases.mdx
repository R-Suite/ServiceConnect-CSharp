ServiceConnect is versioned per-package. Each package ships independently on NuGet; GitHub Releases mark the tagged commits those packages were built from. If you want to know "what changed between v5 and v6 of `ServiceConnect.Interfaces`", you're in the right place.

## Where releases live

- **GitHub Releases** — [github.com/R-Suite/ServiceConnect-CSharp/releases](https://github.com/R-Suite/ServiceConnect-CSharp/releases). Each entry lists the tag, the commit, and a summary of the changes in that cut.
- **NuGet packages** — published under the `ServiceConnect.*` prefix. The core packages are:
  - [`ServiceConnect`](https://www.nuget.org/packages/ServiceConnect) — the bus, hosted service, and dispatch machinery.
  - [`ServiceConnect.Interfaces`](https://www.nuget.org/packages/ServiceConnect.Interfaces) — the public API surface (`IBus`, configuration, handlers).
  - [`ServiceConnect.Client.RabbitMQ`](https://www.nuget.org/packages/ServiceConnect.Client.RabbitMQ) — the RabbitMQ transport.
  - [`ServiceConnect.Persistence.MongoDb`](https://www.nuget.org/packages/ServiceConnect.Persistence.MongoDb) — MongoDB persistence for process managers and aggregators.
  - [`ServiceConnect.Persistence.InMemory`](https://www.nuget.org/packages/ServiceConnect.Persistence.InMemory) — in-process persistence for tests and samples.
  - [`ServiceConnect.Telemetry`](https://www.nuget.org/packages/ServiceConnect.Telemetry) — OpenTelemetry instrumentation hooks.
  - [`ServiceConnect.HealthChecks`](https://www.nuget.org/packages/ServiceConnect.HealthChecks) — `IHealthCheck` integrations for `Microsoft.Extensions.Diagnostics.HealthChecks`.

## Picking a version

Match the major versions of the packages you reference. `ServiceConnect` 7.x expects `ServiceConnect.Interfaces` 7.x; the transport and persistence packages follow the same major line. Mixing majors is unsupported and will surface as binding redirects or missing-method exceptions.

For new applications, take the latest stable of each package. For existing applications, read the release notes for any major version bumps — we call out breaking changes in the GitHub Release body.

## v7 highlights

Version 7 is a reliability, security, and observability pass across the core bus, the RabbitMQ transport, and the persistence providers. If you are upgrading from v6, read the GitHub Release body for the full breaking-change list; the material user-visible shifts are summarised here.

### Supported runtimes

ServiceConnect targets modern .NET only — by design.

- **`net8.0`** — previous LTS. End of Microsoft support: **November 10, 2026**.
- **`net10.0`** — current LTS. End of Microsoft support: November 14, 2028. The library opts into recent BCL features (`System.Threading.Lock`, the `field` keyword) on the hot paths; `net8.0` paths take guarded fallbacks.

All published packages multi-target both: `ServiceConnect`, `ServiceConnect.Interfaces`, `ServiceConnect.Client.RabbitMQ`, `ServiceConnect.Persistence.InMemory`, `ServiceConnect.Persistence.MongoDb`, `ServiceConnect.Telemetry`, and `ServiceConnect.HealthChecks`.

We deliberately do **not** target `netstandard2.x`, `net6.0`, or `net7.0`:

- The hot paths use BCL features that are awkward to polyfill cleanly.
- The remaining LTS surface (.NET 8 + .NET 10) covers every Microsoft runtime with active patch coverage at the time of writing.
- Consumers on .NET Framework or out-of-support .NET Core SKUs can pin earlier ServiceConnect releases that targeted those runtimes; we are not adding support back to the current line.

If your scenario needs `netstandard2.1` (or you'd like to upstream the work), please open an issue.

#### When `net8.0` will be dropped

.NET 8 reaches end of Microsoft support on **November 10, 2026**. ServiceConnect will drop the `net8.0` target framework in the first major version released after that date — current consumers on .NET 8 should plan their migration to .NET 10 LTS during the second half of 2026 or pin to a pre-drop ServiceConnect major.

### Breaking — `ServiceConnect.Filters.MessageDeduplication` removed

The package shipped redelivery dedup in a way that silently dropped legitimate broker redeliveries after a handler crash, recorded keys before the handler ran, and shared in-memory state across instances via a static field. v7 deletes the package outright. Build per-consumer dedupe using the new `OnConsumedSuccessfully` pipeline stage; see the [`CustomFilterAndMiddleware` sample](https://github.com/R-Suite/ServiceConnect-CSharp/tree/master/examples/CustomFilterAndMiddleware) for a worked implementation. Handler-side idempotency remains the canonical answer.

### New — `OnConsumedSuccessfully` filter stage

A fourth pipeline stage that runs only after a successful handler invocation (`result.Success && !result.NotHandled`). Register filters via `builder.AddOnConsumedSuccessfullyFilter<T>()`. Use for at-most-once side effects that depend on the handler having completed: dedupe-key recording, outbox writes, audit events.

### Repository consolidation: 17 projects down to 8

The solution has been pared back from 17 projects to 8: `ServiceConnect`, `ServiceConnect.Interfaces`, `ServiceConnect.Client.RabbitMQ`, `ServiceConnect.Persistence.InMemory`, `ServiceConnect.Persistence.MongoDb`, `ServiceConnect.Telemetry`, `ServiceConnect.HealthChecks`, and the test project. The dropped projects were either experimental transports, abandoned persistence providers, or internal utilities that had no external consumers — removing them cuts build time and clarifies the supported surface.

### MIT relicense

ServiceConnect is now MIT-licensed. Previously the project carried a more restrictive licence that blocked some commercial embedding scenarios; MIT removes that ambiguity.

### Trust boundary on inbound headers

Caller-supplied headers can no longer override the framework's reserved keys. `DestinationAddress`, `MessageId`, `MessageType`, `TypeName`, and `FullTypeName` are now server-authoritative on outbound, and the reply-routing path resolves types through the registered handlers only — the previous fallback to `Type.GetType` on an assembly-qualified wire header is gone. A malicious or buggy publisher can no longer redirect replies or force type loads on consumers.

### End-to-end distributed tracing

`ServiceConnect.Telemetry` now injects the W3C `traceparent`/`tracestate` onto outgoing messages (it already extracted on consume). Spans are tagged with the correct OTel messaging semconv — `publish` for pub/sub and `send` for point-to-point — so dashboards aggregate each traffic shape separately. Trace-context extraction now iterates via the dictionary interface, so header bags wrapped as `ReadOnlyDictionary` no longer silently lose the trace context. See [Observability](/ServiceConnect-CSharp/learn/operations/observability/).

### Breaking — telemetry static state removed

`ServiceConnectActivitySource.Options` and `ServiceConnectActivitySource.MessagingSystemAttributes` are gone. The public `Publish`/`Send`/`Consume`/`SetError` methods now take `ServiceConnectInstrumentationOptions options` and `IMessagingSystemAttributes attributes` as parameters. Two buses in the same process can now have truly independent enrichment delegates and enable-flags. The middlewares pick both up via DI; user code calling `ServiceConnectActivitySource` directly must update.

### Breaking — single ActivitySource

The three sources `ServiceConnect.Bus.Publish`, `ServiceConnect.Bus.Consume`, and `ServiceConnect.Bus.Send` collapse into one named `"ServiceConnect.Bus"`. OTel listener config simplifies to `AddSource("ServiceConnect.Bus")` (or `AddSource(ServiceConnectActivitySource.ActivitySourceName)`). Per-direction enablement remains via `EnablePublishTelemetry` / `EnableConsumeTelemetry` / `EnableSendTelemetry` flags.

### New — `MaxTagValueLength` and `ExceptionMessageSanitiser` options

`MaxTagValueLength` (default 256) bounds user-controlled string tags (destination, routing key, MessageId, conversation id) for cardinality safety. `ExceptionMessageSanitiser` (default null) lets callers redact PII in exception messages before they reach activity status descriptions and `exception.message` event tags. On .NET 9+, when a sanitiser is set, `SetError` opts out of `Activity.AddException` and writes the `exception.*` event attributes manually using the sanitised string.

### Fix — telemetry activity leak on enricher OCE

The user-supplied `EnrichWithMessage`/`EnrichWithMessageBytes` delegate rethrows `OperationCanceledException` by design. Previously, an OCE from the enricher leaked the started activity (the call site never reached the middleware's `finally { activity?.Dispose(); }`). The fix wraps post-`StartActivity` work in `try { ... } catch { activity.Dispose(); throw; }` at all three call sites.

### Fix — body copy gated on listener presence

`TelemetryProcessingMiddleware` previously copied `envelope.Body.ToArray()` for every consumed message regardless of whether any `ActivityListener` was attached. The fix gates the allocation on `ServiceConnectActivitySource.IsConsumeTelemetryEnabled(options)`, which checks both the enable-flag and `ActivitySource.HasListeners()`.

### Health checks

`ServiceConnect.HealthChecks` is a new optional package that ships three opt-in `IHealthCheck` classes for `Microsoft.Extensions.Diagnostics.HealthChecks`: `BusConsumingHealthCheck` (observes `IBus.IsConsuming`), `ConsumerConnectionHealthCheck` (observes `IConsumer.IsConnected`), and `ProducerConnectionHealthCheck` (observes `IProducer.IsHealthy` — a new property promoted to the `IProducer` interface in this release, mirroring the existing `IConsumer.IsConnected`). The package is transport-agnostic and registered through standard `IHealthChecksBuilder` extension methods. See [Observability — Health checks](/ServiceConnect-CSharp/learn/operations/observability/#health-checks) for wiring and the [`ServiceConnect.HealthChecks` reference](/ServiceConnect-CSharp/reference/healthchecks/) for the full API surface.

### Correlation ID reliably on the wire

Outbound paths now stamp `HeaderKeys.CorrelationId` from `message.CorrelationId`. Previously the body-level correlation id was present but the header wasn't, so `IConsumeContext.CorrelationId` defaulted to `Guid.Empty` on the consume side.

### Delivery semantics: audit failures no longer cause redelivery

When auditing was enabled, an audit-publish failure after a successful handler would flip the message into the retry loop and re-run the handler. Audit is now a side-effect on the success path — audit failures are swallowed and logged, never fed back as delivery failures. Malformed `RetryCount` headers route to the error queue instead of silently resetting the retry budget. `HeaderDecoder` tolerates unexpected AMQP header types (interop `long`, `IDictionary`, short-string) instead of throwing and triggering an infinite redelivery loop.

### In-memory persistence no longer drops long-running state at 2 days

The in-memory process-manager and aggregator stores previously set an absolute 2-day expiry on every entry — long-running sagas and slow aggregators silently vanished. The TTL is removed; state lives for the bus lifetime. In-memory persistence now also deep-clones on read to stop caller mutation from corrupting stored state, and the `InMemoryAggregatorPersistor`/`InMemoryPersistenceState` types are disposable so DI rebuilds do not leak timers.

### Process-manager correctness

`DeleteDataAsync` on both the in-memory and MongoDB providers now enforces optimistic concurrency via the `Version` predicate — a concurrent delete racing an update no longer silently wins. The process-manager retry path no longer replays handler side-effects on `ConcurrencyException` — only the state write is retried. MongoDB process-manager collections are keyed on fully-qualified type names; short-name collisions between types in different namespaces no longer share a collection.

### Pipeline lifetimes

Inbound middleware and filters are now resolved per-message from a scoped `IServiceProvider` rather than pinning a transient or scoped instance for the bus lifetime. Startup validation mirrors this on the inbound side — lifetime misconfigurations fail fast instead of manifesting as stale dependencies at runtime.

### RabbitMQ producer and topology hardening

A pass over the RabbitMQ producer's outbound path and the retry-queue declaration. None of these are wire-breaking; they fix observable behaviour, improve diagnostics, or remove surprises latent in earlier point releases.

**Per-delivery `MessageId` for multi-endpoint Send.** Every endpoint resolved by `AddQueueMapping` (or supplied through `SendOptions.EndPoints`) now receives a delivery with a distinct `MessageId` and `TimeSent`. Correlate cross-endpoint deliveries via `CorrelationId`, which remains constant across the fan-out.

**Retry DLX always durable.** The retry dead-letter exchange is now always declared with `autoDelete: false`, regardless of the consumer queue's auto-delete setting. Without this invariant, messages dwelling in the retry queue would be silently dropped after the consumer disconnected. Pre-existing topologies are unaffected on next provisioning.

**Caller-supplied retry args overridden with framework values.** `x-dead-letter-exchange` and `x-message-ttl` in `RabbitMQSettingKeys.RetryQueueArguments` are now overridden silently with framework values at retry-queue provisioning time. A Debug log records each override. Pre-fix, supplying either key threw `ArgumentException` from the AMQP arg merge.

**Publish timeout no longer holds the publish lock during reconnect.** A timed-out publish now marks the connection for reset; the next publish drives the actual reconnect off-lock. Concurrent publishers are no longer blocked behind the worst-case retry budget (~10 minutes by default).

**Producer entry-point null guards.** `Producer.PublishAsync` / `SendAsync` / `SendBytesAsync` now throw `ArgumentNullException` with a useful `ParamName` for null `type` / `message` / `packet` arguments, instead of `NullReferenceException` from later array access.

**Priority-conversion error context.** When a `Priority` header value is non-convertible, the log now includes the offending value and its runtime type instead of a generic "Error setting message priority". The publish continues without priority (advisory semantics preserved).

**Reserved header overwrite warning.** `OutboundHeaderBuilder` now logs a Warning when a caller supplies a reserved header (`DestinationAddress`, `MessageType`, `SourceAddress`, `TimeSent`, `SourceMachine`, `TypeName`, `FullTypeName`, `ConsumerType`, `Language`) — same behaviour as the Bus's reserved-header check, just at a different layer. `MessageId` is preserved for callers that pre-stamp it (e.g. the Bus's authoritative stamp).

**Connection-factory setting errors include key context.** Setting-conversion failures (`Port`, `HeartbeatTime`) now throw `InvalidOperationException` with the setting key, value, and runtime type instead of the raw `FormatException` / `InvalidCastException` / `OverflowException`. The original exception is preserved as `InnerException`.

**`MessageType` header semantics formalised.** The `MessageType` header is the **operation flag** — `"Publish"`, `"Send"`, or `"ByteStream"` — not a CLR type name. **No observable wire change**: the on-wire value has always been one of those three strings. For type information, read `TypeName` (the type's `FullName`) or `FullTypeName` (its `AssemblyQualifiedName`). Downstream auditors that read `MessageType` expecting a type FullName based on out-of-date documentation should switch to `FullTypeName`. Caller-supplied `MessageType` in `IBus.Publish`/`Send` `options.Headers` now flows through to the producer instead of being silently dropped (the producer continues to overwrite it before the wire) — no code-level breakage; existing callers see no change.

### API-shape changes

- **`PublishOptions`** is now a `readonly record struct` matching `SendOptions`. Concurrent `PublishAsync` callers can no longer mutate a shared instance between construction and the async read.
- **`SendOptions.Headers`** and **`PublishOptions.Headers`** are typed as `IReadOnlyDictionary<string, string>?`. Pass any `Dictionary<string, string>`; the framework will not iterate a dictionary another thread might be mutating.
- **`IMessageHandler<T>.Context`** and **`IProcessHandler<T>.Context`** are declared non-nullable. Initialise with `= null!;` to satisfy the nullable-reference analyser — the framework guarantees `Context` is populated before `HandleAsync`.
- **`OutgoingEventArgs.Headers`** is `init`-only — subscribers can mutate individual entries (e.g. stamp a `traceparent`) but cannot swap the whole dictionary out.
- **`IQueueConfiguration`** gains **`AuditRoutingKey`** for routing audit publishes into a topic/direct exchange.
- **`RequestOptions.Default`** returns a fresh instance per access; the previous singleton was mutable and leaked between callers.

## Source and tags

Every release corresponds to a git tag. Browse the source at a specific version by visiting `https://github.com/R-Suite/ServiceConnect-CSharp/tree/<tag>`. The `master` branch is the development head; tagged releases are the frozen points that produced the NuGet artifacts.
